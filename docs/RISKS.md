# Risks

| ID | Risk | Likelihood / Impact | Mitigation | Owner | Status | Escalate when |
|---|---|---|---|---|---|---|
| R-001 | Docker isn't installed on the agent's build machine, so `docker compose up --build` couldn't run. Compose and Dockerfiles are unverified at runtime. | High / High | Compose validated against the official compose-spec JSON schema. App verified outside Docker against a real Postgres. The human runs the compose check. | Human | Open | Compose fails on the human's machine |
| R-002 | `uv` isn't installed on the machine. The agent used a session-only copy. | High / Low | README links the uv install docs. CI installs uv itself. | Human | Open | Human can't run backend checks locally |
| R-003 | Bleeding-edge tool versions (TypeScript 7, Vite 8, Tailwind 4, shadcn 4) may hit incompatibilities later. | Medium / Medium | Lockfiles committed. Pin or downgrade if a later phase breaks. | Agent | Open | A build or type error traced to tooling |
| R-004 | APScheduler isn't a durable queue (§11.4). | Certain / High if ignored | Phase 3: `jobs` table with SKIP LOCKED claims, leases, backoff, dead letters and a one-active-job-per-kind index (D-026). APScheduler only enqueues. | Agent | Mitigated | Jobs stuck in `running` or piling up in `dead_letter` |
| R-005 | LLM model IDs and capabilities may change. | Medium / Medium | IDs come from env. Phase 3 verified `claude-haiku-5-5` via the Models API and the pricing page (D-024). A wrong ID fails fast as a fatal error (job dead-lettered, items untouched). | Agent | Mitigated (classifier); open for the assistant (Phase 6) | Models API stops listing the configured ID |
| R-006 | Source volume may not reach 1,500 raw / 500 processed. | Medium / Medium | Report actual counts. Never fabricate (§11.6). Phase 2: 3,895 unique raw items. Phase 3: **2,607 processed** (VERIFICATION_LOG). | Agent | Closed (targets met with real data) | n/a |
| R-007 | Phase 1 was verified locally on PostgreSQL 18.6 + pgvector 0.8.1, not on the `pgvector/pgvector:pg16` image used by compose and CI. | Medium / Low | Only portable DDL is used (no PG17/18 features). CI runs the integration tests on the pg16 image. | Human | Open | CI integration tests fail |
| R-008 | The startup seed runs in every backend process. A YAML error stops startup. | Low / Medium | YAML is validated in a unit test that runs in CI, so a bad file fails CI first. | Agent | Mitigated | Startup fails after a config edit |
| R-009 | `check_public_url` resolves DNS, then httpx resolves again on connect, which leaves a DNS-rebinding window. | Low (source URLs are admin-controlled; linked article URLs come from HN) / Medium | Every redirect hop is re-checked, bodies are capped, and nothing fetched is executed. Marked with a `ponytail:` comment. Pin the resolved IP in a custom transport if sources ever become user-supplied. | Agent | Accepted | Sources become user-editable |
| R-010 | Source terms were read by the agent, not a lawyer. NYT's RSS terms are limited to personal or non-commercial use. | Medium / Medium | Metadata only for paywalled and AI-opt-out publishers. Every source is documented in SOURCE_REGISTER. The human confirms or disables `nyt_tech` and `ft_tech`. | Human | Open | Any doubt about a source's terms: set `enabled: false` |
| R-011 | Full-text extraction runs 8 threads with no per-host throttle. A batch of new HN links to one site can send up to 8 parallel requests there. | Low / Low | Only new items are fetched; robots.txt is honoured; 10 s timeout, 2 MB cap and 2 attempts. | Agent | Accepted | A site complains or rate-limits us |
| R-012 | The arXiv API sometimes returns HTTP 429 or empty pages (seen during verification). | Medium / Low | Retries with backoff that honours Retry-After; an empty page raises and leaves the checkpoint, so the next run resumes. | Agent | Mitigated | arXiv runs keep failing |
| R-013 | The 40-item evaluation set is small, was labelled by the agent, and informed the v2 prompt change it then measured (D-028). Ambiguous candidates were left out. | Certain / Medium | Both runs reported with denominators; limitations stated in AI_EVALUATION.md. The human reviews every label and records disagreements. A held-out set would be the next step. | Human | Open | Human review changes labels, or spot checks disagree with the eval |
| R-014 | Most Hacker News items are a title only (no description; full text only where robots.txt allows). Classification and summaries of those rest on the headline. | High / Medium | Prompt v2 rates title-only items by headline specificity and caps quality at 60; summaries must not invent details. Spot checks look at HN items specifically. | Agent | Open | Spot checks find invented details in title-only summaries |
| R-015 | The embedding model is downloaded from Hugging Face on first use (unauthenticated, about 70 MB). | Medium / Low | Compose mounts a `models` volume at `FASTEMBED_CACHE_PATH` for the worker. An embedding failure leaves items `processed` with a pending embedding that the next run fills (D-027). | Agent | Mitigated | Repeated "embedding failed" in pipeline logs |
| R-016 | The language check is a heuristic, not a language detector. The first version rejected 283 terse English GitHub descriptions as non-English in the live run (fixed: positive evidence of another language is now required). It still skips relevant non-English items: 27 GitHub repos (Chinese, Korean, Japanese, Russian, Spanish, French, Portuguese), several of them DC tools. | Medium / Low | Regression tests with the real descriptions. Every pre-filter rejection stores its reason in `items.status_reason`, so it can be audited. Non-English skipping is what the plan asks for. | Agent | Mitigated | Spot checks find English items rejected as non-English |
